# ViewRA AI Agent Instructions

**ViewRA**: Self-hosted media server | **Stack**: Go + React/TypeScript | **Architecture**: Clean Architecture / DDD

---

## Critical Rules

### 1. Layer Boundaries

```text
Interfaces (HTTP) → Application (Use Cases) → Domain ← Infrastructure (DB, FFmpeg)
```

- **Domain** (`internal/domain/`): Business logic. Standard lib only. NO external packages.
- **Application** (`internal/application/`): Use cases. Orchestrates domain + infrastructure.
- **Infrastructure** (`internal/infrastructure/`): DB, FFmpeg, filesystem implementations.
- **API** (`internal/api/`): HTTP handlers. Thin layer calling use cases.

### 2. Dual Database Support

All SQL must work on SQLite AND PostgreSQL:

- SQLite queries: `?` placeholders
- PostgreSQL queries: `$1, $2` placeholders
- Run `~/go/bin/sqlc generate` after query changes

### 3. No Adapters or Wrappers

Handlers call use cases directly. No facade structs.

```go
// ✅ Good
type LibraryHandler struct {
    createLibrary *CreateLibraryUseCase
}

// ❌ Bad
type UseCases struct {
    createLib *CreateLibraryUseCase
}
func (uc *UseCases) CreateLibrary(...) { return uc.createLib.Execute(...) }
```

### 4. Vertical Slices

Complete features across all layers before moving to the next feature.

❌ Don't do all entities, then all repos, then all handlers
✅ Do one feature: domain → infrastructure → application → API

## File Placement

| What | Where |
|------|-------|
| Entity | `internal/domain/<entity>/entity.go` |
| Repository interface | `internal/domain/<entity>/repository.go` |
| Repository implementation | `internal/infrastructure/persistence/<entity>/repository.go` |
| SQL queries | `internal/infrastructure/database/queries/sqlite/*.sql` |
| Use case | `internal/application/<entity>/<verb>_<noun>.go` |
| HTTP handler | `internal/api/handlers/<resource>.go` |

## TypeScript/React Style

### Arrow Functions Only

```typescript
// ✅ Correct
const MyComponent = ({ prop }: Props) => {
  return <div>{prop}</div>
}

// ❌ Wrong
function MyComponent({ prop }: Props) {
  return <div>{prop}</div>
}
```

### Exports at End of File

```typescript
// ✅ Correct
const MyComponent = () => { ... }
const helperFn = () => { ... }

export { MyComponent, helperFn }

// ❌ Wrong
export const MyComponent = () => { ... }
```

### Types in Separate Files

```typescript
// Component.types.ts
interface ComponentProps { title: string }
export type { ComponentProps }

// Component.tsx
import type { ComponentProps } from './Component.types'
```

## Common Mistakes

- ❌ Importing external packages in domain layer
- ❌ Empty `sql.NullString{}` placeholders in repositories
- ❌ Creating adapter/wrapper files
- ❌ Using `function` keyword in TypeScript
- ❌ Inline exports in TypeScript

## Development Commands

```bash
make dev              # Start backend (8080) + frontend (5173)
make build            # Production build
make test             # Run tests
make migrate-up       # Run database migrations
~/go/bin/sqlc generate # Generate Go from SQL
make openapi          # Generate OpenAPI spec
make api-client-gen   # Generate TypeScript client
```
